# 实际出片流程与工程验收

完整出片同时执行 [逐素材、逐秒、逐帧制作规范](frame-accurate-production.md)。本文定义阶段和交付，逐帧规范定义各阶段的精度、记录字段与检查证据；两者共同使用。

## 0. 能力和素材检查

确认现有文件、画幅、时长、编码、帧率、音频、字幕、参考片与品牌资源。先检查工具能力和实际文档，再决定用现有剪辑工程、FFmpeg、Remotion、HyperFrames 或其他可用路径。普通裁切/字幕可用简单工具；复杂花字/地图/动画需要可控时间线，不用几十个手写滤镜替代本来可用的工程。

执行实际视频任务时读取环境视频技能：HyperFrames 入口与所需合成/动画/音频文档；已有 Remotion 工程沿用其路由和约定。当前 Skill 定义内容判断，不臆造引擎 API。不因框架偏好重新生成用户已有真人素材。

用户要剪辑真实素材却没提供时，先给最少素材清单与可执行方案；不能生成一段虚构人物影片代替他的旅行。用户明确授权纯 AI 时可推进该路径。付费、凭据、素材上传与外部发布按当前授权处理。

## 1. 项目和素材记录

推荐结构，已有工程则适配而非强制重排：

```text
project/
  brief.md
  design-spec.md
  source-log.csv
  selects.csv
  story-beats.md
  edit-decisions.csv
  cue-sheet.csv
  assets/       # real, generated, graphics, music 等语义分组
  project/      # 实际可编辑工程/代码与依赖说明
  previews/
  exports/
  qa-report.md
```

不要创建没有用途的空文件。最终项目必须能找到它实际引用的素材；源素材过大不随包复制时，提供清楚的相对路径和重连清单，不能说完全自包含。

素材字段：asset_id、file、mode、rights/source、人物、地点、日期、技术属性、可用原声、故事用途、状态。
选择表字段：asset_id、源 in/out、原话、事件、情绪、质量、连续性。
剪辑表字段：shot_id、成片 in/out、asset_id、源 in/out、speed、crop、故事拍点、对白/花字 ID、动效 ID、声音 cue、状态。
时间码明确是秒还是 HH:MM:SS:FF；fps 单独记录。

## 2. 参考研究与设计

默认综艺模式按 [variety-openings.md](variety-openings.md) 单独设计片头与进入正片的交接。片头按主工程精度记录素材、图层、入出帧、关键帧和声音，原创设计具体美术；不能把增加参考名称当成已经实现参考效果。

可访问样片时按 [style-research.md](style-research.md) 确认实际观看覆盖，再按 [animation-playbook.md](animation-playbook.md) 拆成构图、资产、路径/形变/遮挡、文字次序、接镜和声音关系，形成“观察→本片适用理由→具体实现”。没有视频访问则只用已核验公开信息并说明范围。不要为写风格研究下载无法访问或无权使用的节目素材。

设计稿至少包括本片实际所需的字幕、花字、人物/物件处理、地点或任务信息、片头和结尾。强综艺任务另做一个主题场景的峰值构图：本片专属插画/照片切层、前后景、主动作与实拍交接均可指认。不要只在纯色背景排字；先在真实底图和最终观看尺寸确认美术与层级。

沿用现有 design-spec / cue-sheet 记录效果兑现表：`effect_id、选用机制、可见目标、所需资产、实现位置、预览范围、完成状态、未满足项`。每项能指向实际工程和渲染结果；未选机制无需强制凑齐。用户指出缺少的动画、插画与特效属于修正目标，不能仅修改文档称已解决视频问题。

## 3. 粗剪

先搭有完整声音的故事骨架。确认开场承诺、主要事件、地理与时间、结果、情绪出口。对白不能切断原意；没有因果则换选段或缩短故事。

粗剪不需要铺满动效，必须已能理解。素材与目标不匹配时主动收缩事件数量，不把 30 秒装成完整一日综艺。

## 4. AI 生成与补镜

读取 production-guide 的一致性规则。生成顺序：缺镜清单→参考图/人物表→关键帧→短镜头测试→选用→正式生成。先做最可能失败的人物互动与关键地点测试，再批量扩展。失败时检查动作复杂度、参考一致性、空间与光线，调整有证据的问题；不无上限重复同一提示词。

每轮记录模型/工具、提示词版本、任务状态、选用文件和代价（仅已知时）。API 返回任务 ID 不是已完成素材，下载成功也不是质量通过。工具失败或额度/授权受阻时停止相关调用，准确报告。

对生成画面检查首/中/尾帧、人物、手部、服装、物件、地理、运动及可用入出点。不能用后期字卡遮住所有生成错误。复杂对话优先真实原声/经授权配音搭合适画面，避免默认多人物长对白口型生成。

## 5. 精剪、包装、声音

若选择 `full-variety`，按 [variety-effects.md](variety-effects.md) 和 [animation-playbook.md](animation-playbook.md) 先做约 8–15 秒代表样段。样段必须覆盖本次最容易失败的实际机制：分层场景或可动插画、主体与图形互动、设计过的接镜及声音；无法在同一事件中容纳时分成相邻测试段，时长随内容调整。不能只挑最容易的字幕/推近段验证。

先静看峰值构图，再正常速度带声播放；检查插画完成度、动作因果、遮挡与注意中心、文字可读性和声音质感。实际选用机制未兑现时继续修样段，不把同一低完成度模板铺满全片。没有人物时可用景物、食物或物件实现动作链，明确其表现性质。已获授权的制作无需每阶段再问许可；关键项受阻时报告依赖和可行替代，不能隐藏降级。每个效果登记触发事件、时间范围、素材/遮罩/跟踪、动画与声音 cue、实现位置和状态；只列效果名称不算完成。

先锁事件和主要时间，再实现 editing-bible 的相关机制；按 motion-and-sound 实现原创包装与 cue。更改剪点后同步字幕、动画和音效，不能三份时间表各走各的。

地图、预算与分数尽量从同一事件数据驱动。字幕按实际配音/对白对齐，不直接把脚本文本均匀切分。渲染中检查关键帧与中途 seek 的状态，声音与动画不能只在从头播放时正确。

## 6. 预览、修正与停止条件

先低成本预览，不直接等最终长渲染发现版式错误。按本片实际段落覆盖开头、插画/合成、最快对话、任务规则、笑点、地图、风景留白和结尾，不适用项注明。检查图形贴在实拍画面上是否可读。

必须完整播放一个带音频的预览；完成最终导出后，核对文件可打开、时长、编码、画幅、fps、音轨与字幕，并检查首尾与易错段。若输出后有修改，重新验证受影响部分和最终文件，不报告旧版结果。

已确认缺陷要修正；达到用户规格和验收条件后交付，不因主观“还可更好”无限生成。工具问题反复出现时给出具体问题、已完成文件和最短恢复路径，不声称已交付成片。

## 7. 两次验收：效果完成度与工程质量

先评审最终画面，再核查工程和技术，两者独立报告。禁止用分辨率、时长、图层/关键帧数量或 LUFS 代替视觉与声音体验。

### 效果完成度

| 项目 | 通过依据 | 退回信号 |
|---|---|---|
| 本片美术 | 主体插画/图形有足够细节，场景、文字和实拍属于同一设计 | 只有粗几何占位、角标、重复相框 |
| 动画兑现 | 选用机制实际呈现路径、部件、形变或遮挡等需要的行为 | 所有效果都退化为淡入、缩放、滑入 |
| 主体互动 | 图形与真实主体/物件的位置、动作或信息有关，变化有因果 | 贴纸漂在任意空白，换镜仍可照用 |
| 接镜 | 前后镜的锚点、方向、遮挡与声音完成交接 | 随机转场，交叠穿帮，连续使用同一照片卡 |
| 结构变化 | 各段根据事件改变观看方式，强调与留白可理解 | 换图换字却一直是同一版式和同一音点 |
| 声画体验 | 带声播放可判断重音、停顿、环境、音乐质感与可懂度 | 只测响度，未试听却写声音通过 |
| 目标对照 | 用户要求的各项行为有实现与检查证据，缺项明确 | 凭“总体感觉接近”宣称一比一或高还原 |

同一版式可以有意复现，但连续相同或换照片仍完全成立的段落应检查是否需要换观看方式。不是为增加数量而加效果；发现重复时用事件和图形关系改写该段。多种风格目标分别验证，不能只因其中一个做得好就判全片通过。

静态构图检查、连续动作检查、带声播放和技术检查分开记录。在现有 QA 中填实际视频版本、检查范围、观察方式、发现、修复与状态；一秒一帧或每两秒一帧的联系表不能证明短动画/遮罩/跟踪已通过。

### 工程与技术门槛

| 门槛 | 通过依据 | 不通过时 |
|---|---|---|
| 事件 | 可说明人物/目标/行动/结果，或宣传片体验承诺已兑现 | 重新粗剪 |
| 事实 | 原话、关系、路线、结果与素材一致 | 改正文字/画面与结构 |
| 节奏 | 铺垫可理解、笑点不抢跑、快慢有原因 | 调剪点与停顿 |
| 包装 | 手机可读、层级统一、无压脸/平台遮挡 | 改版式与时机 |
| 生成 | 无显著身份漂移、畸形和错误地标 | 换镜、缩镜或重生成 |
| 声音 | 对白清楚、无爆音、环境连贯、音乐不过载 | 重新混音 |
| 技术 | 最终文件可播放，规格正确，无黑帧/丢素材/意外冻结 | 修工程并重导 |
| 交付 | 视频与工程版本对应，依赖/素材可追溯 | 补全再交付 |

可以用“通过/需修正/未检查”，不以漂亮的总分掩盖硬缺陷。不允许把没实际检查的项目写成通过。

## 8. 交付

按用户请求交付实际视频、可编辑工程或源码、SRT/其他合适字幕、素材来源记录与简短 QA。报告视频规格、采用的风格机制、实际检查、尚存限制。字幕文件不含未使用的脚本句子；工程不得包含密钥。

只要求脚本/提示词时交付到相应深度，不额外付费出片。要求成片时不能只交付上述表格。
