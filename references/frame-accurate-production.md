# 逐素材、逐秒、逐帧制作规范

本文件规定完整出片的工作精度。默认使用，不以“用户没有再次要求详细”为由跳过。这里只要求创作方案时，交付相应规划并标明未实现；要实际成片时，记录必须对应真实素材、工程和检查结果。未知值写待测，不能用精细表格伪装成已经观看或已经制作。

## 1. 精度与交付层次

| 层次 | 覆盖范围 | 必须回答的问题 | 对应产物 |
|---|---|---|---|
| 逐素材 | 全部用户提供和实际生成的照片、视频、音频、图形 | 是什么、发生了什么、质量如何、能用哪里、为何选用/淘汰 | 素材记录、联系表、选择表 |
| 逐镜头 | 每段实际上时间线的镜头 | 来自哪个文件哪一段、何时出现、构图/运动/故事作用是什么 | 剪辑决策记录 |
| 逐秒 | 从成片 0 秒到结尾的全部时间 | 此秒的画面、事件、文字、效果和声音是什么，有何变化 | 每秒审阅表，从主时间线派生 |
| 逐帧 | 全片时间范围，以及所有切点/动画/遮罩/跟踪边界 | 每帧由哪些图层合成，各层如何变化，切点有没有残留 | 帧区间记录、关键帧、必要的逐帧修正与检查 |
| 音频采样 | 所有声音事件、对白剪口和混音 | 声音落在哪一时刻，是否错位、截断或爆点 | 声音 cue 与包络、实测结果 |

每帧有确定状态，不等于每帧都要换效果，也不等于每帧写一行重复文字。稳定或可用确定曲线描述的区间采用 `[起帧, 止帧)` 加参数；遇到非连续变化、抠像破边、遮挡和跟踪漂移，再按帧拆分。每秒表同样要写明“延续什么”，不能留空或写“同上”而无法追溯。无需包装的镜头明确写 `none` 和原因。

## 2. 单一时间基准

开工记录画幅、分辨率、时间线帧率有理数 `fps_num/fps_den`、音频采样率、总帧数、色彩处理和实际导出配置；不要把 29.97 当 30。现有工程优先，不能为了套示例随意改帧率。

- 成片帧号从 0 起。所有区间左闭右开：`[in_frame, out_frame)`，时长为两者之差，`out_frame` 不被包含。
- 帧 `f` 的开始时间为 `f × fps_den / fps_num` 秒；展示时间码时注明帧率以及 DF/NDF。时间码只是显示，工程以整数帧或有理时间存储。
- 源视频帧率、PTS 与时间线帧率分别保留。变帧率素材按 PTS 解码并记录；若转固定帧率代理，保留源到代理映射，不能把代理帧号冒充源帧号。
- 常速镜头记录源入出点和倍率。变速镜头保存完整时间映射/速度曲线，定格保存源帧/PTS；倒放写明方向。不能只写“慢一点”。
- 照片没有视频源入出帧，记录文件及方向/裁切；时间线停留范围另记，不能伪造源帧率。
- 声音保留实际时间或 sample offset，不为对齐画面而把所有音频剪点量化到视频帧。画面音点以目标帧定位，声音起始/峰值再按采样微调。
- 秒表由帧时间派生；非整数帧率下，按帧开始时间落入 `[秒数, 秒数+1)` 归档，并保留跨秒事件。末秒按实际结尾截断，不能填到整秒制造多余尾巴。

## 3. 每一份素材的分析卡

对用户提供的全部文件给唯一 `asset_id`。无法读取、重复、损坏和不选用的文件也记录状态与理由；不能只盘点已选文件，然后声称“素材全部分析”。原件不覆盖，代理、抠像、裁切和调色衍生文件关联原 ID。

通用字段：文件路径、内容类型、real/generated/graphic/audio、来源/使用范围、技术信息、实际观察方式、观察覆盖范围、人物、地点、时间依据、主要事件、情绪、可读文字、故事用途、可用性、问题、选择状态、淘汰理由、关联衍生文件。没有核实的名字/地点留未知。

### 照片逐张分析

每张查看实际图像并保留缩略图索引，记录：

1. 原始尺寸、EXIF 方向及实际显示方向；时间/地点元数据只能作为线索，核实后才作为事实。
2. 主体与关系：谁在做什么、视线方向、手部物件、背景地标、是否有可讲的细节；不从表情推断未经证实的心理。
3. 可裁切范围：适合横/竖屏的窗口、人物和关键物件的保护区域、文字与贴纸可放区域、背景延展是否需生成。
4. 画质：焦点、运动模糊、过曝/欠曝、肤色、噪点、已有水印和压缩。区分可修与不可修，不凭缩略图保证高清。
5. 镜头设计：建议停留时长及理由，起止裁切、平移/推拉或保持静止；多人合照避免运镜裁掉关系。
6. 包装机会：人物剪贴、局部细节窗、手账地图节点、情绪花字；需要 mask 时注明实际能力与边缘风险。
7. 与前后镜衔接：颜色、运动方向、人物服装、时间关系、配套原声。照片本身不能证明当时说了某句话。

### 视频逐段分析

先读技术信息并建立覆盖全时长的粗分段/联系表，再完整观看需要纳入叙事的候选段；抽帧只能用于初筛，不能证明对白、动作和反应已理解。未完整看完的文件保留实际已检查范围。

按事件变化拆段，不机械一秒一段。每段记录源 PTS/帧或时间入出点、完整动作的起承转合、人物位置和视线、对白转录/说话人、反应发生点、相机运动、抖动、失焦/遮挡、环境声、可用区间及不宜切断处。需要反应前后余量时保留 handles；多机位同步有依据才合并同一事件。

逐帧复查短暂表情、动作触点、目标出现/离开、定格选帧和拟用切点。不要用均匀抽取的几帧编造完整行动。人物分割/跟踪先测最难的手指、头发、快速运动和前后景遮挡，再决定全段是否可用。

### 音频与图形逐件分析

音频记录时长、采样率、声道、对白/音乐/环境/拟音类别、实际试听范围、可用范围、噪声/削波、对白内容或节拍、来源及许可；响度/真峰值只有实测才填。图形记录尺寸、透明通道、适用背景、缩放质量、字体来源、配色与实际文件位置。音效不要只登记名称而无可用文件。

## 4. 从素材卡到逐镜头决策

每个镜头至少包含：

```yaml
shot_id: S001
status: planned # implemented / rendered / reviewed / rejected
timeline: {in_frame: 0, out_frame: 60}
asset_id: A001
source: {in_pts: null, out_pts: null, time_base: null} # 读取后填；照片可省略该对象
source_mapping: constant # speed_curve / freeze / reverse
speed: 1
story: {beat: setup, visible_event: 待据素材填写, cut_reason: 待填写}
visual:
  crop_start: null # 实际坐标及单位
  crop_end: null
  protected_regions: []
  camera_motion: none
  color_reference: null
dialogue_ids: []
effect_ids: []
audio_cue_ids: []
transition_in: hard_cut
transition_out: hard_cut
implementation_ref: null # 实际工程节点/文件/片段 ID
review: {status: not_checked, issues: []}
```

此处是字段模板，不是已测数据，不把 null 复制成“完成”的工程。按实际引擎适配字段，不要求建立重复的 YAML、CSV 和 JSON 三套源数据。

镜头决策要能说清：为什么选这份素材、为什么从这一帧入、为什么在这一帧出、观众先看什么、什么时候转看文字、声音如何接下一镜。不能以“氛围感”“综艺感”代替这些决定。

## 5. 全片逐秒审阅表

从已实现主时间线导出每秒一行，最低字段如下：

| 秒区间 | 覆盖帧区间 | 主/辅镜头与源段 | 事件和注意中心 | 对白字幕/花字及状态 | 动效/转场及阶段 | 对白/环境/音乐/音效 | 实现与检查 |
|---|---|---|---|---|---|---|---|
| `[0,1)` | 按实际 fps 推导 | 镜号、源 ID、源区间 | 本秒可见变化 | ID、文本、入场/稳定/退场 | ID、关键变化帧 | cue ID、声音行为 | 工程位置、检查状态 |

若同一秒内切镜或换字，列出精确变化帧；不要只写这一秒的开头画面。延续镜头也记录当前裁切、文字和声音的有效区间引用。每秒只承担合理注意任务：动作关键瞬间不同时读长任务卡与地图。

表必须覆盖全长，无遗漏秒段；镜头可以跨秒，音频可以提前进入/延后离开，不为凑整秒强切。每秒表是检查视图，主时间线改动后重新派生，不手动保留旧版。

## 6. 全片帧区间与图层状态

主画面帧区间应覆盖 `[0, total_frames)`。合法叠化、分屏、叠画显式标明合成顺序和混合方式；非故意空档、重复覆盖和越界须修正。黑场、留白、定格是可用创作选择，但标明理由与区间。

每个可见图层记录：ID、类别、起止帧、z 顺序、坐标空间、位置/尺寸、锚点、裁切、透明度、缩放/旋转、文字样式、遮罩、混合方式、变化曲线和工程引用。音轨单列，不能用 z 顺序描述混音。

关键帧记录确切 `frame/value/easing`，说明插值和越界行为；属性没有变化就保持最后值。不用随机抖动或依赖播放历史的效果制造 seek 漂移；程序噪声固定种子并以成片时间求值。导出中每帧状态要可重建。

### 各模块必须写到的细节

| 模块 | 必须指定的状态与边界 | 重点检查 |
|---|---|---|
| 对白字幕 | 说话人、文本、起止帧、分行、基线、字体/字号/描边、背景处理 | 听写准确、断句、换字处不叠字、不截掉必要语气 |
| 吐槽花字 | 情境依据、延迟帧数、内容、字块布局、逐字或整体动作、进/稳/退区间 | 不提前剧透；有阅读时间；动态结束后停稳 |
| 人物定格 | 源精确帧/PTS、冻结区间、背景处理、mask、描边、姓名牌、回动作点 | 表情自然、手发边缘、定格与恢复没有错帧 |
| 贴纸/跟踪 | 主体锚点、坐标采样/关键帧、插值、偏移、遮挡区间、重入规则 | 不漂浮、不穿前景、不突然跳位置 |
| 漫画强调 | 中心点、集中线方向、幅度、冲击峰值帧、回稳帧、文字保护区 | 动作清晰、强度短促、无意外闪烁 |
| 地图 | 地点/照片来源、示意标识、路线顺序、路径进度、小车方向、节点标签时间 | 顺序与事实一致；文字有锚点；不会路线未走完先落终点 |
| 分屏/回放 | 每路源段、裁切、相对时间、标识区间、音频归属、结束方式 | 不暗示虚假同步；回放角标全段存在 |
| 章节/边框 | 节目名、角标、边框开闭区间、画面可用区域、标题动作与声音 | 不挤小关键主体；切章后不残留旧地点 |
| 转场 | 两路重叠帧、运动/遮罩、曲线、落点帧、声音峰值 | 交接连续；转场结束没有 1 帧透明/黑边 |
| 混音 | cue 入出时刻、offset、增益包络、淡化、音乐 duck、总线处理 | 音乐恢复不抢话；尾音完整；无剪口爆点 |

## 7. 十秒原创示例：连续覆盖与帧内变化

以下是未来拍摄或明确虚构情境的设计示例，假设素材中人物确实停下看岔路，随后笑着走向已确认的路；不是现成作品的实测，也不是用户已经提供的素材。30fps，300 帧，`[0,300)`，所有文字和动作须由实际内容替换。

### 每秒视图

| 秒 | 帧区间 | 画面/事件 | 文字与效果 | 声音 |
|---|---|---|---|---|
| 0–1 | `[0,30)` | S01 同伴沿路走，建立环境 | 原创小角标稳定；对白字幕依真实转录 | 脚步/现场原声，音乐低位 |
| 1–2 | `[30,60)` | S01 延续，人物在 f48 开始停步 | f48 前撤掉上一句字幕；保留动作 | 音乐在 f48–60 降低，保留脚步收尾 |
| 2–3 | `[60,90)` | S02 切至真实看路牌反应 | f72 定格，f78 问号开始弹入，f84 到峰值，f88 稳定 | f78 轻提示；定格不循环脚步 |
| 3–4 | `[90,120)` | f108 恢复 S02 动作 | 问号 f96–102 退场；吐槽字 f102–108 入场，随后稳定 | 保留原声；花字入场不再叠第二次大音效 |
| 4–5 | `[120,150)` | S02 真实同伴反应 | 吐槽字稳定；避开眼口和对白区 | 对白优先，音乐继续低位 |
| 5–6 | `[150,180)` | S03 接路牌细节与指路动作 | 吐槽字 f150–156 退场；f156 后只留必要字幕 | 环境声桥，指路原话按实录保留 |
| 6–7 | `[180,210)` | S03 延续，明确前进方向 | 不增加新包装；原角标稳定 | 原声/街声，音乐逐步恢复 |
| 7–8 | `[210,240)` | S04 切回同行动作 | 移除上一地点说明；对白按实际内容 | 脚步接续，音乐回稳 |
| 8–9 | `[240,270)` | S04 延续，走出画面 | 可不加新花字，让动作完整 | 保留笑声尾音 |
| 9–10 | `[270,300)` | S04 延续，承接下场方向 | 小角标到本段末帧，其他效果均已退出 | 下一场环境声可 J-cut，结束点不切断有效声音 |

### 同一样段的帧区间视图

主画面：S01 `[0,60)`；S02 活动段 `[60,72)`；选定真实源帧定格 `[72,108)`；S02 恢复动作 `[108,150)`；S03 `[150,210)`；S04 `[210,300)`。定格之后源时间如何衔接必须在源映射中明确，不能重复一个动作却声称连续。

角标 `[0,300)`，固定位置与样式。问号 `[78,102)`：f78 scale 0.65/opacity 0 → f84 scale 1.12/opacity 1 → f88 scale 1；`[88,96)` 保持；f96 到 f102 缩小淡出，f102 已不存在。吐槽字 `[102,156)`：f102 scale 0.90/opacity 0 → f108 scale 1/opacity 1；`[108,150)` 保持；f150 到 f156 淡出，f156 已不存在。具体 easing 在实现时明确。

音频例：若使用 48kHz，目标 f78 对应 2.6 秒/124800 samples；声音文件若自带前置静音，按真正发声或峰值调整 offset，不能只把文件开头放在 f78 就当同步。此例没有实测响度，不填 LUFS 数字。

这些区间给出了全部 300 帧的主画面和包装状态；不需要写 300 行重复描述。若 f85 抠像边缘破损，单列 f85 的修正与复查，不能用平均评分掩盖它。

## 8. 逐帧检查与证据

制作与审查分开记录。工程能确定每帧状态，不代表每一帧已经人工看过。

1. 素材检查：记录实际看过/听过的范围；抽样和完整检查分别标记。
2. 结构检查：解析工程或由实际引擎导出时间线，检查覆盖、区间、源引用、文件存在、图层顺序和时长；结构通过不等于画面正确。
3. 边界逐帧：所有切点、换字、遮罩启闭、定格恢复、转场首尾，至少检查前后相邻帧；复杂转场覆盖整个变化区间。发现问题扩大检查范围。
4. 效果逐帧：对抠像、跟踪、变形和快速图形变化的完整作用区间逐帧检查，记录漂移/破边并修正。稳定字幕可查首/中/尾与换字边界；不能把抽样检查叫作全片逐帧检查。
5. 每秒审阅：检查全片每秒的事件、信息与声音意图，不通过跳读表格代替播放。关注一秒内多个变化是否抢注意。
6. 全片播放：以正常速度完整观看、试听带音频预览；逐帧看不出喜剧节奏和混音连贯性。必要时手机尺寸再看。
7. 最终导出：确认实际文件规格、时长、总帧数和音轨，复查首尾与易错区间；导出修改过则更新版本与证据。

用户明确要求全片每帧审阅时，按可管理的连续帧段检查完整 `[0,total_frames)`，保留帧号范围、版本、审查方法、发现/修复状态。联系表用于定位，不能替代分辨率足够的帧检查。引擎/显示能力或素材读取受阻时准确报告尚未检查的范围，不能以“AI 自动检查”跳过实际证据。

## 9. 完整制作的交付与更新规则

沿用 production-pipeline 的工程结构，增加本任务实际需要的逐秒视图、帧区间/关键帧数据和审查记录；可整合到一个可检索项目清单中，无需强制拆成很多文件。用户要查看时提供可读表格/页面与可编辑源数据，不能只藏在代码变量里。

完整交付应能从任意秒/帧追到：当前镜头 → 源文件与源段 → 图形/文字 → 动画/遮罩/跟踪 → 声音 cue → 工程实现 → 实际检查结果。每个被淘汰素材仍有去向，不出现“文件没用也没解释”。

修改剪点、速度或片长后，以主工程重新计算镜头、字幕、动画、音频以及每秒视图，重新检查受影响边界。版本绑定素材记录、工程、导出和 QA，不能交付新视频配旧时间表。预览降低分辨率时，最终仍检查抠像和细文字等依赖清晰度的项目。

停止条件是用户要求的成片与详细记录一致，已知问题已修或披露，实际检查范围明确。不能以文件多、表格长、参数精细或技能校验通过，替代实际出片质量验证。
